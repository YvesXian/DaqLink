# DaqLink 通訊協定規格

版本:v0.2(資料封包、命令封包皆已定案)

## 1. 實體層

| 項目 | 設定 |
|---|---|
| 介面 | UART1(PIC32 RF2/RF8)↔ FT232(VCP 模式)↔ PC COM Port |
| 鮑率 | 115200 |
| 格式 | 8N1,無流量控制 |

## 2. 封包格式(所有封包共用)

```
┌──────┬──────┬─────┬──────┬───────────────┬──────────┐
│ 0xAA │ 0x55 │ LEN │ TYPE │ PAYLOAD (LEN) │ CRC16    │
│  1B  │  1B  │ 1B  │  1B  │   0~255 B     │ 2B (LE)  │
└──────┴──────┴─────┴──────┴───────────────┴──────────┘
              └──────── CRC 計算範圍 ─────────┘
```

| 欄位 | 大小 | 說明 |
|---|---|---|
| SOF | 2 B | 固定為 `0xAA 0x55` |
| LEN | 1 B | PAYLOAD 的長度(不含標頭與 CRC),0~255 |
| TYPE | 1 B | 封包種類，見第 3 節 |
| PAYLOAD | LEN B | 內容依 TYPE 而定 |
| CRC16 | 2 B | 計算範圍為 LEN、TYPE、PAYLOAD(不含 SOF),低位元組先送 |

- 所有多位元組欄位一律使用 **little-endian**(低位元組先送)。
- 封包總長度 = LEN + 6。

### 2.1 CRC 規格:CRC-16/CCITT-FALSE

| 參數 | 值 |
|---|---|
| 多項式 | `0x1021` |
| 初始值 | `0xFFFF` |
| 輸入/輸出反射 | 否 |
| 最終 XOR | `0x0000` |
| 檢查值 | ASCII `"123456789"` → `0x29B1` |

韌體與 PC 端的 CRC 實作都必須以此檢查值做單元測試。

### 2.2 接收端解析規則

```
IDLE ──0xAA──→ SOF1 ──0x55──→ LEN → TYPE → PAYLOAD(LEN bytes) → CRC_L → CRC_H
  ↑              │(非 0x55)                                                │
  └──────────────┘                                            驗證 CRC ────┘
```

- CRC 正確：交給上層處理，回到 IDLE。
- CRC 錯誤:CRC 錯誤計數 +1,從該封包 SOF 的**下一個 byte** 開始重新搜尋 `0xAA 0x55`(不可整包丟棄，避免漏掉緊接在後的正確封包)。
- 本協定不做 byte stuffing,資料中出現 `0xAA 0x55` 時，靠 LEN + CRC 驗證排除誤判的同步。

## 3. 封包種類(TYPE)

| TYPE | 方向 | 名稱 | LEN | 說明 |
|---|---|---|---|---|
| `0x01` | MCU → PC | DATA | 14 | 資料封包，見第 4 節 |
| `0x10` | PC → MCU | START | 0 | 見第 5 節 |
| `0x11` | PC → MCU | STOP | 0 | |
| `0x12` | PC → MCU | SET_RATE | 2 | |
| `0x13` | PC → MCU | SET_WAVE | 8 | |
| `0x14` | PC → MCU | GET_STATUS | 0 | |
| `0x80` | MCU → PC | ACK | 1 | 見第 6 節 |
| `0x81` | MCU → PC | NAK | 2 | |
| `0x82` | MCU → PC | STATUS | 8 | |

TYPE 範圍劃分:`0x01`~`0x0F` 為 MCU 主動送出的資料,`0x10`~`0x7F` 為命令,`0x80`~`0xFF` 為命令回應。

## 4. 資料封包(TYPE = 0x01)

每個取樣 tick 送出一包,LEN = 14。

| Offset | 欄位 | 型別 | 說明 |
|---|---|---|---|
| 0 | `seq` | u16 | 取樣序號，每個 tick +1,超過 65535 後回到 0 |
| 2 | `dac_a` | u16 | 本 tick 寫入 MCP4922 通道 A 的 code(0~4095) |
| 4 | `dac_b` | u16 | 本 tick 寫入 MCP4922 通道 B 的 code |
| 6 | `adc0` | u16 | MCP3304 CH0(接 VOUTA) |
| 8 | `adc1` | u16 | MCP3304 CH1(接 VOUTB) |
| 10 | `adc2` | u16 | MCP3304 CH2(接 GND,預期 ≈ 0) |
| 12 | `adc3` | u16 | MCP3304 CH3(接 VREF,預期 ≈ 4095) |

### 4.1 範例

`seq=1, dac_a=2048, dac_b=1024, adc=2047/1025/0/4095`:

```
AA 55 0E 01 01 00 00 08 00 04 FF 07 01 04 00 00 FF 0F 75 E3
└SOF┘ LEN TYP └seq┘ └dacA┘└dacB┘└adc0┘└adc1┘└adc2┘└adc3┘└CRC┘
```

CRC = `0xE375`,傳送順序為 `75 E3`。

### 4.2 設計說明

- **封包內帶 DAC code**:PC 端直接以實際寫入 DAC 的值和 ADC 讀值比較，不需自行推算波形與對齊相位。由於 VREF 共用(比例式量測),理想上 `adcN = dac_x`,差值即為迴路誤差(LSB)。
- **時間基準使用 `seq`**:timestamp = `seq_unwrapped / 取樣率`。FT232 的 latency timer(預設 16 ms)會讓資料成批到達，因此不使用 PC 的接收時間當 timestamp。
- **`seq` 溢位處理**:PC 端計算 `diff = (ushort)(seq - prev_seq)`。`diff == 1` 為正常;`diff > 1` 表示遺失了 `diff - 1` 筆資料。
- **12-bit 資料不壓縮**:以 u16 傳送，犧牲 25% 頻寬以換取兩端實作與除錯的簡單性。

### 4.3 頻寬

115200 8N1 的有效頻寬為 11,520 byte/s,每包 20 byte:

| 取樣率 | 資料量 | UART 使用率 |
|---|---|---|
| 100 Hz | 2,000 B/s | 17% |
| 200 Hz | 4,000 B/s | 35% |
| 500 Hz | 10,000 B/s | 87%(不建議) |

在 115200 下，取樣率上限定為 **200 Hz**。

## 5. 命令封包(PC → MCU)

### 5.1 START(`0x10`,LEN = 0)

將 `seq` 歸零並開始採樣。採樣中再次收到 START 仍回 ACK(冪等),`seq` 不歸零。

### 5.2 STOP(`0x11`,LEN = 0)

停止採樣。已停止時再次收到 STOP 仍回 ACK(冪等)。

### 5.3 SET_RATE(`0x12`,LEN = 2)

| Offset | 欄位 | 型別 | 說明 |
|---|---|---|---|
| 0 | `rate_hz` | u16 | 取樣率,10~200 Hz |

- **僅限停止狀態下使用**,採樣中收到會回 NAK `0x04`。原因：採樣中改變取樣率會使 `時間 = seq / rate` 失去依據。
- 韌體實作:Timer2(16-bit),PBCLK 80 MHz、prescaler 1:256,`PR2 = 312500 / rate_hz − 1`(10 Hz → 31249,200 Hz → 1561)。
- 上限 200 Hz 來自 115200 鮑率下的頻寬限制(見 4.3)。

### 5.4 SET_WAVE(`0x13`,LEN = 8)

| Offset | 欄位 | 型別 | 說明 |
|---|---|---|---|
| 0 | `ch` | u8 | 0 = 通道 A、1 = 通道 B |
| 1 | `wave` | u8 | 0 = DC、1 = 正弦、2 = 三角、3 = 方波 |
| 2 | `freq_x10` | u16 | 頻率,0.1 Hz 為單位(15 = 1.5 Hz);DC 時忽略 |
| 4 | `amp` | u16 | 振幅(code),波峰到中心的距離;DC 時忽略 |
| 6 | `offset` | u16 | 中心值(code);DC 時即為輸出值 |

- 採樣中可使用，從下一個 tick 生效。
- 參數檢查(不符合回 NAK `0x03`):
  - `ch` ≤ 1,`wave` ≤ 3
  - `offset − amp ≥ 100` 且 `offset + amp ≤ 3995`(避開 MCP4922 軌限區域)
  - 非 DC 時:`freq_x10 / 10 < rate_hz / 2`(Nyquist)
- DC 模式可用於靜態誤差量測：逐點設定 `offset` = 100~3995,比對 ADC 讀值。

### 5.5 GET_STATUS(`0x14`,LEN = 0)

MCU 回傳 STATUS 封包(見 6.3),不另外回 ACK。PC 端斷線重連後，可用它取得 MCU 的目前狀態。

### 5.6 開機預設值

| 項目 | 預設值 |
|---|---|
| 狀態 | 停止 |
| 取樣率 | 100 Hz |
| 通道 A | 正弦波 1 Hz,amp 1500,offset 2048 |
| 通道 B | 三角波 1 Hz,amp 1500,offset 2048 |

## 6. 命令回應(MCU → PC)

### 6.1 ACK(`0x80`,LEN = 1)

| Offset | 欄位 | 型別 | 說明 |
|---|---|---|---|
| 0 | `cmd` | u8 | 收到的命令 TYPE |

### 6.2 NAK(`0x81`,LEN = 2)

| Offset | 欄位 | 型別 | 說明 |
|---|---|---|---|
| 0 | `cmd` | u8 | 收到的命令 TYPE |
| 1 | `err` | u8 | 錯誤碼(見下表) |

| `err` | 意義 |
|---|---|
| `0x01` | 未知命令 |
| `0x02` | LEN 與命令規定不符 |
| `0x03` | 參數超出範圍 |
| `0x04` | 採樣中不允許此命令 |

### 6.3 STATUS(`0x82`,LEN = 8)

| Offset | 欄位 | 型別 | 說明 |
|---|---|---|---|
| 0 | `running` | u8 | 0 = 停止、1 = 採樣中 |
| 1 | `reserved` | u8 | 固定為 0(對齊用) |
| 2 | `rate_hz` | u16 | 目前的取樣率 |
| 4 | `rx_crc_err` | u16 | MCU 收到的 CRC 錯誤累計次數 |
| 6 | `tx_drop` | u16 | TX ring buffer 已滿而丟棄的資料封包累計數 |

## 7. 通訊流程規則

- **Stop-and-wait**:PC 一次只送一個命令，收到回應後才送下一個。等待逾時 200 ms 則重送，最多重試 3 次，仍失敗即視為斷線。
- **CRC 錯誤不回應**:CRC 錯誤代表整包內容(包括 TYPE)都不可信，因此 MCU 只將 `rx_crc_err` +1,不回 NAK,由 PC 端逾時重送。
- **回應與資料封包共用同一條資料流**:PC 端解析器依 TYPE 分派處理。韌體端寫入 TX ring buffer 時必須一次寫入整個封包，不可讓回應插進資料封包的中間。

| SET_RATE 100 Hz | `AA 55 02 12 64 00 45 83` |

| ACK(START) | `AA 55 01 80 10 05 F2` |
| NAK(SET_RATE,採樣中) | `AA 55 02 81 12 04 57 40` |
| DATA(見 4.1) | `AA 55 0E 01 01 00 00 08 00 04 FF 07 01 04 00 00 FF 0F 75 E3` |
